# MockPad — 実装スライス

状態: V1〜V4の初版実装・ローカル検証済み（2026-10-24）。
[Shape A](shaping.md)と[breadboard](breadboard.md)に基づく。各スライスは画面からデモできる単位。
個別スライス計画は作成せず、この文書の受け入れ条件に沿って実装した。

## 一覧

| Slice | 利用者に見える成果 | Shape parts | 要件 |
|---|---|---|---|
| V1 | 部屋を作ってURLを共有し、別ブラウザーと同じコードを編集できる | A1/A2/A7の基本 | R0/R1/R7/R8/R8.2 |
| V2 | 言語・インデント・相手の位置・自分だけのUndoが使える | A3/A4/A5 | R1.1/R4/R5/R6.1/R6.2/R6.3 |
| V3 | 接続状態が見え、一時切断後に自動で共同編集へ戻れる | A6 | R1.2 |
| V4 | 面接官が部屋を終了でき、全員不在24時間で自動削除される | A7の終了・期限管理 | R8.1 |

R2/R3は全スライスで対象外。スパイクのHTTP/stdinブリッジは本体に流用せず、本番用のWebSocket経路を実装する。
以下は受け入れ条件と実装順の記録。個別の実機未検証事項は末尾に区別する。

## V1: 部屋を作成して共同編集する

**デモ**: 面接官が表示名を入力して部屋を作り、参加URLをコピーする。別のブラウザーで受験者が入室し、両者の入力が双方へ反映される。

| 種別 | 追加するaffordances |
|---|---|
| Places | P1/P2/P3/P5/P6 |
| UI | U1/U2/U3/U4/U5/U6/U7の初回接続表示/U11/U12/U16 |
| Code | N1/N2/N3/N4/N5/N6/N8の本文同期/N11/N17/N20/N21/N22/N23/N24/N25/N27 |
| Stores | S1/S2/S3/S4/S5/S6 |

配線: U2→N1→N2→S1/S4→P3/N4→N21/N25→N22→N8→U6。U11→N11→S6。相手のU5→N3→N4→N22。編集はU6→N6→N22→N5→N22→相手のN8→U6。

受け入れ条件:

- ログインなしで作成・入室でき、1 URLにつき1コードだけ表示する。
- 参加URLに管理シークレットが含まれず、作成ブラウザーだけが管理権限を得る。
- 同時編集で両方の変更が統合され、日本語・絵文字・改行が壊れない。
- 後から入室した受験者が最新コードを取得できる。
- 不正・存在しない部屋IDで新しい部屋を暗黙作成しない。
- サーバー再起動後は古いURLが利用不可になり、空の部屋として復活しない。
- スパイクで確認したMonacoのaliasとYrs `small-client`を本体のビルドに反映する。

## V2: 面接用エディターの操作を揃える

**デモ**: 面接官が言語とタブサイズを変えると受験者にも反映される。相手の名前・色・カーソル・選択範囲が見える。片方のUndoで相手の編集が消えない。

| 種別 | 追加・拡張するaffordances |
|---|---|
| UI | U6のインデント・Undo操作/U8/U9/U10/U17/U18 |
| Code | N7/N8の設定反映/N9/N10/N18/N19/N26 |
| Stores | S2のY.Map/UndoManager/Awareness、S5のAwareness |

配線: U9/U10→N7→S2→N26でローカル反映し、N6→N22→N5→N22→相手のN8/N26で共有する。選択はU6→N9→N22→N10→N22→N8/N19→U8。UndoはU6/U17/U18→N18→N6→同じ本文同期経路。

受け入れ条件:

- 言語とタブサイズはどちらが変更しても両者に反映され、後からの入室でも現在値を取得できる。
- 登録言語の選択とハイライトを実画面で確認する。少なくともJavaScript、Python、Rustで言語別インデントを確認する。
- 指定した幅のスペースでTabが動作し、Enterも選択言語の規則に応じてインデントする。既存コードの字下げを自動検出して共有設定を上書きしない。
- 自分だけのUndo/RedoをWindowsのCtrl+Z/Ctrl+Y、macOSのCmd+Z/Cmd+Shift+Z、および提供するメニュー経路で確認する。Monacoの通常Undoへ抜ける経路を残さない。
- 設定変更と相手の編集は自分のコードUndoへ混入しない。
- 別ブラウザーで、名前ラベル・色・カーソル・選択範囲の見た目を確認する。相手の編集で位置がずれても表示を追従する。

## V3: 切断から復帰する

**デモ**: 受験者側のネットワークを切ると再接続中になり、編集が一時停止する。復旧後、自動で同期し、再読み込みせず編集を再開できる。

| 種別 | 追加・拡張するaffordances |
|---|---|
| UI | U7の再接続表示、U6の編集可否、U8の退出・再入室 |
| Code | N12/N15/N29の切断・heartbeat処理、N4/N22/N5の再同期、N9/N10/N19の参加者復元 |
| Stores | S3の接続状態、S5の接続寿命、S1の不在開始時刻 |

配線: 切断→N12→N27→U7/U6→N4→N21/N25→N22→N8→N27で編集再開。サーバー切断検出はN22/N29→N15→S1/S5→N22→N8/N19→U8。

受け入れ条件:

- 接続中・同期中・接続済み・再接続中を区別して表示する。
- 初期同期前と切断中は本文・共有設定を編集不可にする。送信直前の変更をタブ内に保持し、復旧時に統合する。
- WebSocketの再接続が自動で行われ、ユーザーの手動同期操作を要求しない。
- 相手が切断中に行った編集、未送信の自分の編集を統合し、重複配信でも本文を重複挿入しない。
- 切断参加者の表示を除去し、再接続時に復元する。
- 受験者の再読み込み後も現在コードを取得できる。Undo履歴の復元は行わない。
- 部屋不在の場合は再試行を止めてP5へ移る。

## V4: 部屋を終了・期限切れにする

**デモ**: 面接官が終了を確認すると、両者の画面が終了表示に変わる。全員が不在の部屋は24時間で利用できなくなる。期限内の再入室では残っている。

| 種別 | 追加・拡張するaffordances |
|---|---|
| Places | P4 |
| UI | U13/U14/U15、U16の終了理由 |
| Code | N13/N14/N16/N28、N25の入室時期限確認、N17の終了通知処理 |
| Stores | S1の状態遷移と削除、S5の切断、S3の終了理由 |

配線: U13→P4→U15→N13→N14→N24→N16→N22→両者のN17→P5/U16。最後の切断→N15→S1、不在24時間後→N28またはN25→N16とS1からの除去。

受け入れ条件:

- 受験者は終了ボタンを持たず、APIを直接呼んでも部屋を終了できない。名前を面接官と同じにしても権限は得られない。
- 面接官のキャンセルでは部屋が存続し、終了成功後は両者のコード表示・再接続を終了する。
- 通信エラーや権限エラーを終了成功として表示しない。
- 仮想時刻で24時間の直前・ちょうど・直後を検証する。実際に24時間待つテストはしない。
- 未入室の部屋は作成時刻、最後の退出後は退出時刻から起算する。
- 誰かが接続している間は無入力でも削除しない。期限内の再入室はタイマーを解除し、再度全員退出したら新たに起算する。
- 清掃前でも期限切れ時点から入室を拒否する。入室と清掃、更新と終了を競合させ、削除後にデータを復活させない。
- 部屋とコードをディスクへ保存せず、削除後の古いURLで新規作成しない。

## 実装時の完了判定

本体の通常画面・API/WebSocket経路で`tests/e2e.mjs`の14項目が合格した。
Rustの5テストでは24時間の直前・ちょうど・直後、接続中の保持、最終退出、不在期限の入室時確認、管理権限、古いハンドルの更新拒否を確認した。
実行コマンドはREADMEを参照。最新の機械可読結果と画面は生成物`test-results/`に出力する。

### 残る検証範囲

- macOS実機でのCmd+Z/Cmd+Shift+Z。キーバインドは実装済みだがWindows上の試験で代用したと主張しない。
- 組み込み全言語のハイライト・インデント。E2EではJavaScript/Python/Rustを確認。
- 不安定な実回線・別端末・リバースプロキシ越しの通信。E2Eはローカルの2ブラウザー環境とWebSocket経路の接続遮断を使う。
- 入室と清掃の高負荷での競合。ロック順序と終了状態で直列化し、期限時の入室拒否と削除済みハンドルの更新拒否をテストしている。
