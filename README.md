# MockPad

面接官と受験者が、URLで同じ部屋に入り、コードを共同編集する模擬面接用サービス。
通話と面接後の講評・振り返りはDiscordで行います。

RustとMonaco Editorによる初版です。ログインなしで部屋を作り、参加URLを共有して利用できます。

## できること

- 1部屋1コードのリアルタイム共同編集
- 言語別のシンタックスハイライト、部屋で共有する言語・タブサイズ
- Enterの自動インデントと、スペースを使うTab入力
- 参加者の表示名・色・カーソル・選択範囲の共有
- 自分の編集だけを取り消すUndo／Redo（ボタン・キーボード・右クリックメニュー）
- 接続状態の表示と、一時切断後の自動再接続
- 面接官だけが行える部屋の終了

部屋とコードはRustサーバーのメモリー上だけに保持します。
面接官が終了するか、全員不在のまま24時間経過すると削除します。誰も入室していない部屋は作成から5分で削除します。サーバー再起動時の復元はしません。
コード実行、通話、チャット、面接履歴、フィードバック保存は含みません。

## ローカルで起動

Node.js 24、npm、Rustのstableツールチェーンが必要です。リポジトリ直下で実行します。

```sh
npm ci
npm run build
cargo run --release --locked
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)を開きます。
PowerShellでnpmの実行ポリシーに制限がある場合は、`npm`を`npm.cmd`に置き換えてください。

1. 面接官が表示名を入力して部屋を作成します。
2. 「参加URLをコピー」で取得したURLを、Discordなどで受験者に共有します。
3. 受験者が表示名を入力して入室します。
4. 通話しながら同じコードを編集します。
5. 面接官の「部屋を終了」で、部屋とコードを削除できます。

同じブラウザープロファイルでは、再読み込み後もCookieで面接官を識別します。
参加URLには管理情報を含めません。別ブラウザーへの管理権限移譲はありません。

## 開発

ターミナルを2つ使います。

```sh
# ターミナル1: Rust API・WebSocketサーバー
cargo run --locked

# ターミナル2: フロントエンド開発サーバー
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173)を開きます。APIとWebSocketはViteからRustへ転送します。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `MOCKPAD_ADDR` | `127.0.0.1:3000` | Rustサーバーの待受アドレス |
| `MOCKPAD_PUBLIC_ORIGIN` | 未設定 | 公開時のブラウザー側Origin。例: `https://mockpad.example.com` |
| `MOCKPAD_TRUSTED_PROXY` | 未設定 | `X-Real-IP`を信用する直近のプロキシのIP。例: `127.0.0.1`。HTTPS公開時は必須 |
| `MOCKPAD_BASE_PATH` | 空文字列 | 配信する子パス。例: `/mockpad`。フロントエンドのビルド時とRustの起動時に同じ値を指定 |

HTTPSのリバースプロキシ配下では`MOCKPAD_PUBLIC_ORIGIN`と`MOCKPAD_TRUSTED_PROXY`を指定し、`/api/rooms/{id}/ws`のWebSocket転送を有効にします。
`https://`を指定した場合は管理CookieにもSecure属性を付けます。
初版は単一プロセス用です。GitHubリポジトリの公開と、サービスのホスティングは別の作業です。

子URLで配信する場合、プロキシは`/mockpad/api/rooms/...`などのパスをそのままRustへ転送してください。
nighthawkへの配置と最終適用は[デプロイ手順](deploy/nighthawk/README.md)を参照してください。

## 公開時の制限

メモリーと通信量を制限するため、次の上限を設けています。HTTPでの入室・作成制限は`429`を返し、不正な入力や通信上限に達したWebSocketは送信者だけを切断します。

| 対象 | 上限 |
|---|---|
| 部屋数 | サーバー全体で32部屋、送信元単位で保持中の部屋8個まで（入室済み・空室も含む） |
| 未入室の部屋 | 作成から5分で削除。入室後は全員退出から24時間 |
| 同時参加者 | 1部屋8人、サーバー全体で256接続（接続処理中も含む） |
| 部屋作成 | 送信元単位で1分間10回 |
| WebSocket接続試行 | 送信元単位で1分間30回 |
| WebSocket入力 | 1メッセージ256 KiB、1接続あたり毎秒120メッセージ・1 MiB、1部屋あたり毎秒400メッセージ・2 MiB |
| 部屋の編集履歴 | 受信更新の累計2 MiB、CRDTの構造・削除範囲の累計50,000件 |
| 参加者情報 | 1件2 KiB、表示名40 UTF-16単位、部屋の累計クライアントID数256 |
| 送信待ち | 接続ごとに16メッセージ・2 MiB + 64 KiB、1回の送信待ちは5秒 |
| 全体同期の要求 | 1接続につき文書同期と参加者情報の問い合わせを各1回まで |

編集履歴の上限には削除済みの内容、保留中の更新、再接続時の再送も含みます。履歴上限に達した場合は新しい部屋を作成してください。送信が追いつかない接続も切断します。

接続元IPにはTCP接続の相手を使い、`X-Forwarded-For`は信用しません。`MOCKPAD_TRUSTED_PROXY`と実際のTCP接続元が完全一致する場合だけ、単一の有効な`X-Real-IP`を利用者IPとして扱います。ヘッダーの欠落・複数指定・不正な値は拒否します。それ以外の接続からのIPヘッダーは無視します。

制限の送信元単位はIPv4アドレス、またはIPv6の`/64`です。IPv4射影IPv6は対応するIPv4と同じ単位にします。IPv6の一時アドレス変更で別枠にならないための集計であり、利用者本人の識別ではありません。複数のIPv4や異なるIPv6 `/64`を同じ所有者として結び付けることはしません。プロキシの信頼判定にはこの集約を使いません。

プロキシは利用者が送った`X-Real-IP`を必ず上書きしてください。nginxの場合は`proxy_set_header X-Real-IP $remote_addr;`を指定します。公開時はプロキシ側でも利用者IPごとに接続数・要求頻度・要求サイズを制限し、Rustの待受ポートをインターネットへ直接公開しないでください。同じNAT出口を使う利用者は保持数と作成頻度の上限を共有します。

共有文書はプレーンテキストと設定の文字列・タブサイズ（2・4・8）に限定し、ネストした配列・オブジェクト・共有型はYrsでのデコード前に拒否します。項目IDの参照先が同じ文書型・設定キーに属することも確認し、未確認の参照や型の混在を拒否します。転送する更新はサーバーが実際に適用した差分から生成します。参加者情報は名前・色・選択位置の型と値を検査します。

HTTP応答にはCSP、フレーム埋め込み禁止、`nosniff`、外部へのReferer送信禁止、カメラ・マイク・位置情報の無効化を設定します。CSPのインラインスタイル許可はMonacoの表示と参加者カーソル用です。Monaco内蔵のDOMPurifyはViteのaliasで修正版3.4.17に置き換え、配信バンドルにも旧版が残らないことを検証します。

## 検証

```sh
cargo fmt --check
cargo clippy --locked -- -D warnings
cargo test --locked
npm run build
cargo build --locked
npm run test:e2e
cargo build --release --locked
npm run test:security
```

E2Eは専用サーバーを`127.0.0.1:3187`に起動し、独立した2つのブラウザー環境から実画面を操作します。
Windowsではインストール済みのMicrosoft Edgeを使います。Linuxでは次のコマンドでChromiumを準備します。

```sh
npx playwright-core install --with-deps chromium
```

Rust側の24テストで終了権限、期限境界、入力と文書型の検証、同期要求の制限、送信元の識別、作成・送信制限、子パスとCookieの範囲を確認します。
E2Eの15項目では共同編集、Undo／Redo、設定、まとめて貼り付け、インデント、参加者表示、再接続、終了、再起動などを確認します。
Windows/Edgeで検証済みです。macOS実機でのCmdキー操作と、インターネット経由の端末間通信は未検証です。
結果とスクリーンショットは`test-results/`に出力します。GitHub Actionsでも同じ検証を実行します。
セキュリティ回帰テストは本番用のreleaseビルドを`127.0.0.1:3192`に起動し、不正な参加者情報、4,096段のネスト、通信頻度、参加者数、作成上限、HTTPヘッダー、配信バンドルを確認します。
